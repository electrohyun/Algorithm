# 그래프 탐색 — DFS 개념 학습 (문제 미완)

## 오늘 한 것

- 문제를 풀지 못함. **DFS 개념 학습 ~30분** 위주.
- 대상 문제: 프로그래머스 네트워크 (43162)
- 폴더 정리: `bfs/` → `graph/` 로 변경 (BFS만이 아니라 그래프 탐색 전반 담는 폴더로).

## 오늘 학습한 개념 (DFS)

- 인접 리스트: 배열 안에 배열. 인덱스 = 노드 번호, 값 = 연결된 노드들의 배열.

```js
// 간선: 1-2, 1-3, 2-4, 3-4 (양방향)
const graph = [[], [2, 3], [1, 4], [1, 4], [2, 3]];
// 0 1 2 3 4 ← 인덱스 = 노드 번호
```

양방향이므로 간선 하나당 graph[a].push(b)와 graph[b].push(a) 둘 다 실행.
0번 인덱스는 안 쓰고 비워둠(노드가 1번부터).

- 재귀 DFS 코드

```js
const visited = new Array(5).fill(false);

function dfs(node) {
  visited[node] = true;
  console.log(node);
  for (const next of graph[node]) {
    if (!visited[next]) dfs(next);
  }
}
dfs(1);
```

- 콜스택 변화 순서 (위 그래프에서 dfs(1) 실행 시)

```js
  [1] visited[1]=true, 출력 1, graph[1]=[2,3] → 2로 진입
  [1,2] visited[2]=true, 출력 2, graph[2]=[1,4] → 1은 visited, 4로 진입
  [1,2,4] visited[4]=true, 출력 4, graph[4]=[2,3] → 2는 visited, 3으로 진입
  [1,2,4,3] visited[3]=true, 출력 3, graph[3]=[1,4] 둘 다 visited → return
  [1,2,4] for문 끝 → return
  [1,2] for문 끝 → return
  [1] 다음 이웃 3 확인 → 이미 visited → for문 끝 → return
  [] 종료
```

출력 순서: 1 2 4 3

핵심: dfs(next)를 만나면 그 자리에서 함수가 끝까지 다 실행되고 나서야
for문의 다음 반복으로 넘어감. 1의 이웃 3은 2 쪽 탐색이 완전히 끝난 뒤에
확인되고, 그때는 이미 visited[3]이 true.

- visited 표시 위치 두 가지

  (1) 진입 직후 표시 — 위 코드. 시작 노드 표시가 함수 안에 포함됨.

  (2) 호출 직전 표시

```js
visited[1] = true; // ← 시작 노드는 함수 밖에서 직접 표시
function dfs(node) {
  for (const next of graph[node]) {
    if (!visited[next]) {
      visited[next] = true;
      dfs(next);
    }
  }
}
```

(2)에서 시작 노드 표시를 빠뜨리면 dfs(1) → dfs(2) → graph[2]의 1이
아직 false → dfs(1) → 무한 재귀. 표시 위치를 옮기면 시작 노드 처리도
같이 옮겨야 함.

재귀 DFS에서는 dfs(next) 호출 즉시 그 함수가 실행되므로, 표시 시점 차이
사이에 다른 호출이 끼어들 수 없음. 두 방식의 실행 결과는 같음.
이 차이가 실제로 결과를 바꾸는 건 스택·큐를 직접 만들어서 여러 노드를
한꺼번에 넣는 경우(중복 삽입 발생).
