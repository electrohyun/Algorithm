# Day26 (2026년 08월 11일)

# 프로그래머스 42885 구명보트

문제: https://school.programmers.co.kr/learn/courses/30/lessons/42885

## 문제에서 놓치면 안 되는 조건

- 한 보트에는 최대 2명만 탈 수 있다.
- 보트에 탄 사람들의 몸무게 합은 `limit` 이하여야 한다.
- 모든 사람을 태우는 데 필요한 보트 수의 최솟값을 구한다.

## 풀이 흐름

1. 몸무게를 오름차순으로 정렬한다.
2. `first`는 가장 가벼운 사람, `end`는 가장 무거운 사람을 가리킨다.
3. 가장 가벼운 사람과 가장 무거운 사람이 같이 탈 수 있으면 둘 다 보낸다.
4. 같이 탈 수 없으면 가장 무거운 사람은 누구와도 같이 탈 수 없으므로 혼자 보낸다.
5. 배열의 원소를 삭제하지 않고 두 포인터만 이동한다.

## 코드

```js
function solution(people, limit) {
  const peopleArray = people.sort((a, b) => a - b);

  let first = 0;
  let end = peopleArray.length - 1;
  let answer = 0;

  while (first <= end) {
    if (peopleArray[first] + peopleArray[end] <= limit) {
      answer++;
      first++;
      end--;
      continue;
    }

    if (peopleArray[first] + peopleArray[end] > limit) {
      answer++;
      end--;
      continue;
    }
  }

  return answer;
}
```

## 시도별 정리

### 1번 풀이: 가장 가벼운 사람끼리 태우기

- 처음에는 한 보트에 최대 2명이라는 조건을 놓치고, 무게 제한까지 여러 명을 채우려고 했다.
- 최대 2명 조건을 반영한 뒤에도 가장 가벼운 두 사람부터 태워서 오답이 났다.
- `[40, 40, 60, 60]`, `limit = 100`에서 `40 + 40`, `60`, `60`으로 보내면 3대가 필요하지만, `40 + 60`으로 두 번 보내면 2대면 된다.
- 오답의 직접적인 원인은 `shift()`가 아니라 누구를 함께 태울지 정한 기준이었다.

### 2번 풀이: 배열 삭제와 포인터 이동을 함께 사용

- 가장 가벼운 사람과 가장 무거운 사람을 비교하는 방향은 맞았다.
- 하지만 `shift()`와 `pop()`으로 배열을 줄이면서 `first`와 `end`도 이동했다.
- 배열의 인덱스가 다시 배치된 뒤에도 포인터를 추가로 움직여 `undefined`를 참조했고, 두 조건이 모두 실행되지 않으면서 무한 반복이 발생했다.
- `shift()`는 한 번 실행할 때 남은 원소를 앞으로 옮기므로, 반복해서 사용하면 최악의 경우 `O(n²)`이 될 수 있다.
- `pop()`은 배열의 마지막 원소만 제거하므로 일반적으로 `O(1)`이다.

### 3번 풀이: 배열을 유지하고 포인터만 이동

- 정렬한 배열을 변경하지 않고 `first`와 `end`만 움직였다.
- `first <= end`인 동안 아직 처리하지 않은 사람이 남아 있다.
- 매 반복에서 가장 무거운 사람 한 명은 반드시 보트를 타므로 `answer`를 1 증가시킨다.

## 정당성

- 가장 가벼운 사람과 가장 무거운 사람의 합이 `limit`보다 크다면, 가장 무거운 사람은 그보다 무거운 다른 사람과도 같이 탈 수 없다. 따라서 혼자 보내는 것이 확정된다.
- 두 사람의 합이 `limit` 이하라면 함께 보내도 된다. 가장 무거운 사람을 처리하면서 가장 가벼운 사람도 함께 처리해 남은 사람들의 짝 가능성을 보존한다.

## 시간복잡도

- 정렬: `O(n log n)`
- 투포인터 순회: `O(n)`
- 전체: `O(n log n)`

## 회고

오늘의 발견:

- 문제의 핵심 조건 하나를 놓치면 풀이의 전제 자체가 달라질 수 있다.
- 투포인터에서는 배열을 직접 삭제하지 않고, 포인터가 아직 처리하지 않은 구간을 나타내게 할 수 있다.
- 반복문 안의 `shift()`는 `O(n²)` 가능성을 먼저 확인해야 한다.

잘한 점:

- 1번 풀이가 틀렸다는 것을 확인한 뒤 기존 방식에 매달리지 않고 다시 설계했다.
- 2번 풀이에서 가장 가벼운 사람과 가장 무거운 사람을 비교하는 방향을 직접 떠올렸다.
- 배열 삭제와 포인터 이동을 함께 사용한 문제를 찾아 포인터만 이동하는 3번 풀이로 통과했다.

불확실한 점:

- 문제를 읽을 때 제한사항뿐 아니라 문제 설명에 포함된 핵심 조건까지 빠짐없이 확인해야 한다.
- 반복문 안에서 `shift()`, `unshift()`, `splice()`, `includes()`, `indexOf()`, `filter()`, `slice()`, `sort()`를 사용한다면 전체 시간복잡도를 먼저 계산해야 한다.

내일부터:

- 투포인터를 사용할 때 두 포인터가 무엇을 가리키고 어떤 조건에서 움직이는지 먼저 적는다.
